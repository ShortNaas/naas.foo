# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- **Primary:** Engineering leaders, engineering managers, and technical recruiters evaluating Naas for backend, distributed systems, or security engineering roles.
- **Secondary:** Peer developers, open-source collaborators, and privacy advocates reviewing code, utilities, or technical writing.

## Product Purpose

Establish immediate technical credibility as a security-focused backend developer and privacy advocate. Success means qualifying visitors and prompting direct contact via email or LinkedIn for relevant technical opportunities.

## Positioning

An uncompromisingly lightweight, privacy-respecting personal presence. Unlike generic template portfolios, naas.foo reflects backend discipline and Unix philosophy through zero external runtime dependencies, minimal vanilla code, client-side email scraper resistance, and authentic technical projects.

## Operating Context

- Evaluated primarily on desktop and mobile web browsers during recruitment screening, technical referrals, or code audits.
- Evaluated alongside GitHub profile (`github.com/shortnaas`), professional profiles (`linkedin.com/in/shortnaas`), and external blog essays (`naas.work/blog`).
- Static web serving via standard HTTP servers (e.g. `python3 -m http.server 8000`) without compilation or build pipelines.

## Capabilities and Constraints

- **Capabilities:** Terminal-themed single-page layout; section navigation with scroll observation; dynamic client-side project rendering via `projects.json`; bot-resistant obfuscated email reveal; extensible blog feed integration stub.
- **Constraints:** Pure vanilla HTML, CSS, and minimal vanilla JavaScript (~30 lines). No frontend frameworks, no bundlers, no external dependencies.
- **Privacy & Security:** Zero third-party trackers, zero cookies, zero analytics. Protected contact credentials.

## Brand Commitments

- **Identity:** Naas — Security-focused backend developer, Linux user, privacy advocate.
- **Handles & Links:** `shortnaas` on GitHub, X, LinkedIn; primary email via Proton (`jonasget@proton.me`); domain `naas.foo`.
- **Voice:** Direct, concise, technical, no marketing fluff or corporate jargon.

## Evidence on Hand

- Live projects recorded in `projects.json`: Cambridge Dictionary Parser for Anki, Man United PL Countdown, WeQuote (ZenQuote Telegram bot), Social Circles (contact manager based on Derek Sivers' 'hundreds').
- Code repository at `https://github.com/shortnaas`.
- External blog and essays at `https://www.naas.work/blog`.
- *Absences:* No corporate testimonials, client logos, commercial case studies, or pricing claims exist; future work must not fabricate them.

## Product Principles

1. **Substance Over Decoration:** Prioritize real code, technical depth, and clean implementation over visual gimmicks.
2. **Minimalism and Zero Bloat:** Preserve zero-dependency vanilla architecture and lean payloads.
3. **Privacy and Respect by Default:** Zero tracking, zero telemetry, bot-resistant contact details.
4. **Authentic Unix Voice:** Reflect a command-line and systems engineering mindset in structure and interaction.

## Accessibility & Inclusion

- Semantic HTML structure (`<nav>`, `<main>`, `<section>`, `<footer>`, semantic heading levels).
- Noscript fallback for projects and clear link affordances.
- Keyboard navigation and accessible color contrast.
